# 中国科大网球预约助手

[English](README.md) | 简体中文

面向“中国科大体育运动场馆预约”小程序的实验性预约助手。通过本机已登录的小程序获取当前会话和新的 `noise`，由 Python 查询场地、构造预约请求并核对订单结果。

**公开仓库是脱敏源代码，不是下载后即可使用的成品。** 使用者需要自行准备本人账号配置、有效签名配置和兼容的小程序运行时调试环境。

## 已实现功能

- 按日期、连续时段及场地优先级预览可预约场地。
- 使用已添加的同伴，校验账号和请求参数。
- 获取新的 `noise`、生成签名并进行单次预约提交。
- 提交后查单，区分待同伴确认、正式确认及结果未知。
- 使用 SQLite 持久记录每个 15 分钟时间格，避免超时、重启或换场后重复提交。
- 一次性前台定时执行，默认只演练。

正常查场和提交不依赖鼠标选场，但仍依赖微信、目标小程序和本机调试器保持运行。

## 环境与前置条件

- Windows、Python 3.10 或更新版本、Node.js 22 或更新版本。
- 本人已正常登录微信及目标小程序，并具备场馆预约资格。
- 独立安装的 [WMPFDebugger](https://github.com/evi0s/WMPFDebugger) 及其依赖。
- 本人的账号与已添加同伴信息，以及与当前客户端匹配的私有签名配置。

Python 代码使用标准库；运行时桥接依赖调试器目录中的 Node.js 依赖。适配器使用以下目录结构：

```text
ustc_tennis/
├── booking.py
├── config.json
├── account.local.json
├── signing.local.json
└── work/runtime-validation/WMPFDebugger/
    ├── src/index.ts
    └── node_modules/
```

已验证过 WMPF 25510，其他版本需重新确认兼容性。WMPFDebugger 通过 Frida 修改本机运行时，可能受到版本更新或检测机制影响；它不是微信官方开放接口，也无需将使用者添加为学校小程序开发者。

本仓库不包含调试器源码、依赖或本地加固补丁。安装和使用时应遵循上游说明与许可证，确认调试服务仅监听回环地址，不要向其他设备转发端口。使用结束后关闭调试器。

## 配置文件

先复制示例文件；如已有自己的配置，请保留原文件，不要覆盖：

```powershell
Copy-Item config.example.json config.json
Copy-Item account.example.json account.local.json
```

### 预约偏好：config.json

```json
{
  "date": "2030-01-01",
  "start": "23:00",
  "end": "23:30",
  "courts": [1, 2, 3],
  "share_open": true
}
```

示例日期需要替换为实际打球日期。

| 字段 | 含义 |
| --- | --- |
| `date` | 打球日期，格式为 `YYYY-MM-DD`；立即执行时仅允许当天或次日 |
| `start` | 开始时间，北京时间，分钟为 `00`、`15`、`30` 或 `45` |
| `end` | 结束时间，支持 `24:00`；单次连续时长为 30–90 分钟 |
| `courts` | 小程序显示的场号，按优先顺序选择第一个满足完整时段的场地 |
| `share_open` | 是否向好友展示本次预约，填写 `true` 或 `false` |

例如，`[5, 4, 7]` 表示优先 5 号场，其次 4 号场，再选 7 号场；只要 7 号场则填写 `[7]`。程序内部会将显示场号映射为接口 ID，无需在这里填写 `121` 等内部编号。当天接口未返回的场地会被拒绝。

JSON 不支持注释。重复字段、未知字段、错误类型和不合法时间都会被拒绝。场地优先级仅用于提交前选择，不代表失败后会不断换场重试。

### 账号与同伴：account.local.json

```json
{
  "expected_open_id": "REPLACE_WITH_YOUR_OWN_ACCOUNT",
  "companion_ids": [12345]
}
```

两个值均为占位示例，必须替换为本人的真实账号标识和已添加同伴 ID。程序会根据同伴列表推导人数，并验证当前微信账号是否匹配。不要猜测其他人的 ID。

新格式配置默认读取同目录的 `account.local.json`。如果把预约配置放在其他目录，也需要在该目录准备对应的账号文件。

### 私有签名配置：signing.local.json

该文件是包含 `suffix` 字符串的 JSON 对象。公开仓库不提供有效值；随意填写字符串不能产生有效签名。它必须与当前客户端匹配，并留在本机。

## 运行步骤

以下命令在仓库根目录的 PowerShell 中执行。

### 1. 离线检查配置

```powershell
python booking.py check-config --config config.json
```

仅检查格式和本地账号配置，不证明当前已登录或场地可用。

### 2. 启动运行时调试器

准备好前述独立依赖后执行：

```powershell
.\start-debugger.ps1
```

保持该终端运行，然后打开目标小程序。若微信要求重新登录，由本人完成。不要同时连接多个调试客户端。

### 3. 在另一个终端实时预览

```powershell
python booking.py preview --config config.json
```

该命令获取实时场地及订单数据，不调用预约提交接口。默认预览报告保存在 `preview.latest.json`。

### 4. 单次真实提交

确认预约配置后执行：

```powershell
python booking.py submit --config config.json
```

**这条命令会创建真实预约。** 程序获取新的 `noise`，再次检查会话一致性，提交一次并查单核对。默认结果报告保存在 `booking-validation.json`。

## 一次性定时执行

```powershell
python scheduler.py --at '2030-01-01T17:00:00+08:00' --config config.json
```

上述日期只是格式示例，请替换为实际触发日期。`--at` 是执行时间，`config.json` 的 `date` 是打球日期；若预约次日场次，两者通常相差一天。

默认只演练，不创建订单。确实需要到点提交时才添加 `--submit`：

```powershell
python scheduler.py --at '2030-01-01T17:00:00+08:00' --config config.json --submit
```

这是一次性前台进程，不会注册系统后台任务或每天循环。需保持电脑唤醒、微信和调试器在线。配置或账号文件在等待期间变化、迟到超过 30 秒、检测到时钟跳变时，程序会停止。

到点后仍需进行实时检查，触发时间不等于请求抵达服务器的时间；不保证放号高峰一定抢到场地。

## 结果状态

| 状态 | 含义 |
| --- | --- |
| `config_valid` | 本地配置格式通过检查 |
| `preview` | 实时预览通过，未提交 |
| `pending_companion` | 订单已创建，等待同伴确认 |
| `confirmed` | 服务端订单成功且同伴状态均为已同意 |
| `unknown` | 可能已创建，但暂时无法核实；不要直接重试 |
| `rejected` | 服务端明确拒绝，不自动重发 |
| `stopped` | 配置、会话、防重或运行条件不满足 |

已观察到的预约须知规定：同伴确认前保留 1 小时预约资格，同伴确认后才正式预约成功。待确认不是永久锁场，具体规则以小程序当前说明为准。

## 限制与故障处理

- **网络或会话失效：** 先检查微信、小程序和调试器是否正常；程序不自动登录，也不重放旧 `noise`。
- **提交结果未知：** 先在小程序查看订单。程序不会因超时自动再发一次 POST。
- **取消后仍被防重拦截：** 本地 `booking-ledger.sqlite3` 的时间格占位不会自动释放，提交前失败也采用保守保留策略。需核实实际订单状态后定点处理，不能直接删除整个账本来重试未知结果。
- **日期未开放或额度不足：** 当天及次日的开放时间、本人和同伴资格、每日额度最终由服务器判定；单次配置合法不代表仍有剩余额度。
- **已有订单过多：** 查询逐页进行，最多 10 页；无法确认完整数据时停止提交。
- **微信更新或运行时关闭：** 调试连接可能失效，需要重新确认环境兼容性。

目前不提供无限重试、并发抢占、自动恢复登录或无人值守运行保证。

## 数据与隐私

公开源码保留目标服务域名和小程序 AppID，用于限定调用对象；它们不属于登录凭据。仓库不包含真实账号、token、私有签名值、抓包、小程序包或真实订单记录。

`.gitignore` 已排除本地账号配置、签名配置、账本和运行数据。提交代码前仍需检查暂存内容，不要公开原始抓包、解包文件或运行时输出中的会话信息。
